# Data flow

Every Remotify run is a **funnel**: volume enters at scrapers and exits as Telegram alerts + Application queue rows. This page is the stage contract; [Pipeline](/docs/pipeline) covers cron budgets and failure taxonomy.

## Stage contracts

| # | Stage | Input | Output | Owner |
| --- | --- | --- | --- | --- |
| 1 | Scrape | Registry of sources | Raw job arrays (possibly empty) | `scrapers/registry.js` |
| 2 | Normalize | Raw jobs | Canonical title/skills/location | `normalizers/index.js` |
| 3 | Dedupe | Normalized + recent DB | Unique candidates | `utils/deduplicate.js` |
| 4 | Quality | Deduped jobs | Title/remote/ATS-ranked subset | `utils/job-quality.js` |
| 5 | Cap | Quality list + settings | ≤ `max_jobs` (cron further caps) | `pipeline.js` |
| 6 | AI score | Capped jobs + profile brief | score / matched / missing / reason | `ai-batch.js` + Gemini |
| 7 | Persist | Scored jobs | Upserted `Job` rows | Prisma via pipeline |
| 8 | Notify | Jobs ≥ notify gate | Telegram (+ PDF), `isNotified` | `notification.js` |
| 9 | Enqueue | Jobs ≥ apply gate | `Application` queued rows | `apply/queue.js` |

## Two score gates (not one)

<Figure caption="Notify is stricter and smaller. Apply enqueue is wider but prefers auto-submit ATS.">
  <ThresholdCompare />
</Figure>

| Gate | Default | Setting key | Purpose |
| --- | --- | --- | --- |
| Notify | **85** | `min_match_score` | Only interrupt you for excellent fits (top 5) |
| Apply enqueue | **75** | `apply_min_score` | Fill daily quota with auto-ATS preference |

That is why the funnel chart can show **enqueue &gt; notify**: different thresholds and different selection policies.

## Identity of a job through the funnel

1. Scraper produces an `applyUrl` (must survive Zod).  
2. Normalize may rewrite title/skills but **keeps URL identity**.  
3. Dedupe keys primarily on normalized apply URL, then company+title, then similarity.  
4. Persist upserts on unique `Job.applyUrl`.  
5. Application links to `jobId` and stores ATS type from `detectAtsType(applyUrl)`.

## Triggers that start the funnel

| Trigger | Path | Notes |
| --- | --- | --- |
| Vercel cron | `POST /api/cron` | UTC 02:00 & 12:00 typical; Bearer secret |
| Run now | Settings UI → `/api/settings/run-now` | Manual operator |
| Scripts | `npm run test:pipeline`, `scrape:persist` | Local debugging |

All should converge on `runPipeline()` so behavior stays single-sourced.

## What you should see after a healthy run

1. `RunHistory` row with counts and `status` success/partial  
2. New/updated `Job` rows with `aiScore`  
3. Telegram top matches (if credentials + scores)  
4. New `Application` rows if apply enabled + quota remaining  
5. Later: worker claim/report moving statuses
