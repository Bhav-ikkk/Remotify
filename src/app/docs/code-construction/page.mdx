# Code construction

This page explains **how the codebase is constructed and managed** — file ownership, recurring patterns, and the rules for adding features without forking the architecture.

## Construction philosophy

Remotify is intentionally a **single Next.js ESM app** (no TypeScript sources today, no microservices). Complexity lives in clear modules under `src/services/` with thin route wrappers.

| Pattern | Where | Intent |
| --- | --- | --- |
| Registry array | `scrapers/registry.js` | One place to add sources |
| Zod boundary | `scrapers/schema.js` | Invalid jobs never enter transform |
| Strategy facade | `services/ai/index.js` | Swap Gemini without touching pipeline |
| Sequential AI | `utils/ai-batch.js` | Avoid 429 storms |
| Settings JSON bag | Prisma `Setting` | Avoid schema churn for knobs |
| Brain/hands split | queue API + worker | Browser work stays local |
| Soft failure | scrapers return `[]` | One dead source ≠ dead pipeline |
| Adapter map | `workers/apply/adapters` | ATS-specific selectors isolated |

## How a feature is added (management rule)

1. **Decide the layer** (scraper / transform / AI / apply / surface).  
2. **Extend the owning module** — do not invent a parallel path.  
3. **Keep Prisma changes intentional** — prefer Settings JSON for knobs.  
4. **Document behavior** in these MDX docs (and BDD on Normalization when product rules change).  
5. **Expose ops** via script or Telegram only if operators need it daily.  
6. **Smoke** with the smallest script that proves the layer (`test:scrapers`, `apply:smoke`, dry worker).

## File-level construction map

### Ingress — scrapers

```text
src/scrapers/
  registry.js       ← ONLY list of { name, label, run }
  schema.js         ← JobSchema / ScraperOutputSchema
  http.js           ← shared axios defaults / headers
  ats-boards.js     ← public ATS APIs + target-companies.json
  remotive.js / remoteok.js / himalayas.js / arbeitnow.js / underdog.js
  skipthedrive.js / builtin.js / jobgether.js  ← cheerio HTML
  wellfound.js      ← Zyte items
  test-runner.js    ← npm run test:scrapers
```

**Do:** keep `run()` pure enough to unit-run.  
**Don’t:** call Prisma or Gemini from a scraper.

### Transform — normalize, dedupe, quality

```text
src/normalizers/index.js
src/utils/deduplicate.js
src/utils/similarity.js
src/utils/job-quality.js
src/utils/ai-batch.js
src/utils/zyte-cloud.js
```

### Intelligence

```text

src/services/ai/gemini.js     ← concrete provider
src/services/profile.js       ← buildAiMatchProfile()
src/services/resume/
  template.js / tailor.js / pdf.js
```

```text
src/services/pipeline.js      ← runPipeline()
```

### Apply path

```text

  queue.js    ← enqueue / claim helpers / digests
```

### Surfaces


## API construction rules

| Route family | Auth | Body owner |
| --- | --- | --- |
| `/api/cron` | Bearer `CRON_SECRET` | calls `runPipeline` |
| `/api/settings/**` | operator-trusted deploy | Zod validate knobs |
| `/api/apply/claim` | worker bearer | returns application + identity |
| `/api/apply/report` | worker bearer | status machine updates |
| `/api/telegram/webhook` | optional secret token | bot command dispatch |

Routes stay thin: parse → call service → JSON. Business rules do not live in `route.js` files.

## Data construction rules

- **Unique apply URL** is the job identity.  
- **Application status** is the only apply state machine — don’t invent side tables for “in flight”.  
- **Settings** for knobs; **env** for deploy secrets (env wins when both exist for Gemini).  
- **RunHistory** is append-only telemetry — don’t overwrite history rows for new runs.

## UI construction rules

- Marketing `(marketing)` vs app `(app)` route groups keep shells separate.  
- Docs use MDX + `src/components/docs/*` charts — not screenshots of Notion.  
- Radix Themes for CRM controls; docs/landing may use bespoke CSS.

## Testing & verification scripts

| Script | Proves |
| --- | --- |
| `test:scrapers` | Sources return parseable jobs |
| `test:pipeline` | Orchestration path locally |
| `verify:grab` | Excel export path |
| `apply:smoke` | Worker ↔ API handshake |
| `apply:worker:dry` | Adapter without submit |
| `score:backfill` | Score old jobs without full scrape |

## Anti-patterns (reject in review)

- Calling `@google/genai` from a scraper or React component  
- Copy-pasting Greenhouse selectors into Lever adapter  
- Storing long-term queue state only in memory  
- Committing `data/*.personal.json`  
- Adding a second “pipeline2” script that bypasses `runPipeline`  
- Documenting behavior only in chat — update MDX
