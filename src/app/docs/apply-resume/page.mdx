## End-to-end sequence

```text
pipeline.enqueueEligibleJobs()
    → Application (queued, atsType, aiScore)
worker loop
    → POST /api/apply/claim   (Bearer)
    → generateMasterResumePdf (Gemini light tailor + pdfkit)
    → runAtsAdapter (greenhouse | lever | ashby | else needs_review)
    → POST /api/apply/report
    → optional nodemailer digest + Excel
Telegram: /approve /skip /approvals /apply_status /apply_digest /resume
```

## Enqueue policy

Owner: `src/services/apply/queue.js`.

| Rule | Default / behavior |
| --- | --- |
| Min score | `apply_min_score` (75) |
| Daily quota | `daily_apply_quota` (35) UTC day |
| Prefer auto ATS | `apply_prefer_auto_ats` — Greenhouse/Lever/Ashby first |
| Dedupe | Skip existing job ids / urls / apply keys |
| Feature flag | `apply_enabled` must be true |

Workday / unknown ATS can still be recorded but land in **needs_review** unless you later expand `AUTO_SUBMIT_ATS`.

## ATS detection

Owner: `src/services/apply/ats.js`.

| Signal | Type |
| --- | --- |
| `greenhouse.io`, `gh_jid` | `greenhouse` |
| `lever.co` | `lever` |
| `ashbyhq.com` | `ashby` |
| `myworkdayjobs.com`, `wdN.myworkday…` | `workday` (detect only) |
| else | `unknown` |

`canAutoSubmit(type)` is the gate adapters must honor.

## Claim / report contract

### Claim `POST /api/apply/claim`

- Auth: `Authorization: Bearer $APPLY_WORKER_SECRET` (or `CRON_SECRET`)  
- Effect: `queued` → `preparing`  
- Returns: application row + `ApplicationIdentity` facts for form fill  

### Report `POST /api/apply/report`

- Accepts terminal-ish statuses: `submitted | needs_review | failed | skipped | queued` (and submitting progress as implemented)  
- Stores error text / timestamps for CRM  

Exact JSON fields evolve in route handlers — treat services as source of truth and keep worker/report in sync.

## Local worker

Owner: `src/workers/apply/run.js`.

| Env | Role |
| --- | --- |
| `APPLY_API_BASE` | Brain base URL |
| `APPLY_WORKER_SECRET` | Bearer |
| `APPLY_DRY_RUN` | `1` = no real submit |
| `APPLY_WORKER_MAX` | Max claims per process |
| `APPLY_DELAY_MS` | Pace between apps (~150s default idea) |
| `APPLY_HEADED` | Show browser for debug |

Schedule helper: `npm run apply:worker:schedule` (Task Scheduler friendly).

## Adapters

```text
adapters/index.js     ← dispatch by atsType
adapters/greenhouse.js
adapters/lever.js
adapters/ashby.js
```

**Construction rule:** selectors and click paths stay inside the adapter. Shared wait/upload helpers can be extracted carefully; never leak Greenhouse DOM assumptions into Lever.

### Failure modes

| Symptom | Likely | Action |
| --- | --- | --- |
| Always `needs_review` | Unknown ATS / captcha / login wall | Manual apply + `/approve` |
| `failed` quickly | Selector drift | Headed dry-run; fix adapter |
| Claim 401 | Secret mismatch (or no secret configured — auth fails closed) | Align worker env with Vercel |
| PDF missing / queue halted | No complete master resume in DB | Run `npm run resume:sync` |

## Resume pipeline

1. **Locked master resume in Postgres** — `CandidateProfile.masterResume`, imported via `npm run resume:sync` (demo file only via explicit `RESUME_DEMO=1`).  
2. **Light tailor** — `services/resume/tailor.js` emphasizes relevant skills; **no invented employers**.  
3. **PDF** — `pdfkit` Helvetica LETTER via `generateMasterResumePdf`.  
4. **Provenance** — exact uploaded bytes stored as `ResumeArtifact` (sha256); download via `GET /api/applications/:id/resume`.  
5. **Delivery** — upload to ATS + Telegram `/resume` + per-application email attachment.  

Deprecated: prefer tailor/template path over legacy `master.js` helpers.

## Identity

`ApplicationIdentity` holds the form facts (name, email, phone, links, work auth). It is a **live projection** of the DB master resume — every queue/claim re-syncs contact facts, so stale seeds can never lock in wrong data. If no complete master resume exists, identity resolution fails loudly (Telegram alert) instead of substituting placeholders.

## Operator checklist (first safe apply)

1. `APPLY_DRY_RUN=1` smoke against staging/local  
2. Confirm claim returns identity  
3. Watch headed Greenhouse fill  
4. Flip dry-run off for one job  
5. Verify Applications CRM + Telegram digest
